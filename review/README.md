# 편집 작업대

독자 탐색은 [전체 목록](../memes/README.md), [분야별 목록](../collections/topics.md), [최근 선별](../collections/latest-year.md)에서 합니다. 이 폴더는 후보·보류·수정 대상을 관리하며, 여기에 등록했다고 사전에 수록되거나 사실 검증이 끝난 것은 아닙니다.

## 후보 처리
`candidates.json`의 workflow는 `discovered` → `reviewing` → `ready` → `published` 순서로 관리합니다. 불확실하면 `held`, 범위 밖이면 `rejected`로 남깁니다. 보류 이유와 next_step을 적어 다음 조사에서 같은 실패를 반복하지 않게 합니다. 공개 본문에 조사 로그를 붙이지 않습니다.

## 분야가 없는 항목
빈 tags를 모두 조사 부족으로 취급하지 않습니다.
- `pending`: 분야 검토 전 또는 근거 부족. 기본값.
- `domain_independent`: 검토했지만 특정 분야에 묶기 어려운 표현.
- `classified`: 실제 분야 태그가 있는 항목. 본문 tags에서 자동 판정.

`tag-decisions.json`에는 태그 없는 항목에 대한 편집 판단만 기록합니다. 표제어·별칭·태그 자체를 복제하지 않습니다. domain_independent에는 판단 이유를 반드시 남깁니다. 이전의 미분류 29개는 자동으로 검토 완료 처리하지 않습니다.

## 작업 순서
1. 기존 제목·별칭을 검색해 중복과 파생형을 구별합니다.
2. 실제 사례를 확인해 뜻·예·유래를 검토합니다. 확인할 수 없으면 후보에 남깁니다.
3. 본문을 추가·수정하고 관련 링크는 연결 이유와 함께 한쪽에만 작성합니다.
4. 관찰 월을 입증한 경우에만 본문에 월별 링크를 추가합니다.
5. `python scripts/build_navigation.py`로 전체·월별 목록과 빠진 역링크를 생성합니다.
6. `python scripts/build_index.py`로 검색/분야 목록을 생성합니다.
7. 구조 검사, 생성물 검사, 단위 검사를 실행합니다. 생성 성공은 사실 검증이 아닙니다.

## 기록 보존
[과거 시험 보고서 안내](../reports/README.md). 이전 파일명과 링크는 호환을 위해 유지합니다. 과거의 수량·브랜치·검사 결과는 당시 기록이며 현재 상태를 뜻하지 않습니다.
