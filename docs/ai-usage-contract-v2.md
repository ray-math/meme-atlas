# AI 사용 맥락 검색 계약 v2

이 계약은 외부 AI 호출자가 사용할 지시문이다. 저장소 CLI가 자연어를 직접 이해하거나 LLM을 호출한다는 뜻이 아니다.

## 질의 단계

1. 사용자의 요청이 의미 조회인지 실제 사용인지, 단순 일반 도움인지 구분한다. 중대한 정보나 대화 방향이 없으면 clarify. 고통 축소·소문 확정·금융 보장·명시적 비밈 요청에는 밈추천에서 abstain하고 필요한 일반 도움을 준다.
2. search_usage.py --describe-facets의 현재 정의를 읽는다. 명확한 밈 이름이 있으면 query에 그 이름을 넣고 추측한 이름을 만들지 않는다.
3. 이름이 없다면 가장 확실한 대화기능 한 축을 우선 선택한다. 상황이 명시적이고 기능보다 더 정확하면 상황 한 축을 선택한다. 비슷하지만 다른 기능 후보는 같은 축의 OR로 검색한다. 장면 속 감정을 해당 표현의 필수 감정 조건으로 옮기지 않는다.
4. 목표는 먼저 후보를 이해하는 것이므로 mode=lookup으로 후보를 조회한다. 이것은 사용 승인이나 recommend 제한의 자동 완화가 아니다. 조회 후 별도의 문맥 판정을 반드시 수행한다. 명시적 비속어 제외 같은 금지 조건은 exclude_risks로 유지한다.
5. 서로 다른 축을 2개 이상 AND로 강제하는 것은 실제로 둘 다 필수라고 확인한 경우만 허용한다. 보통 1개 핵심 축이면 충분하다. 질문 내용을 복사한 긴 query를 문자열 검색기에 넣지 않는다.
6. 후보가 없으면 없는 것을 만들어 답하지 않는다. 다른 질의를 쓴다면 이유와 추가 질의를 별도 기록한다. 이번 평가에서는 비교를 위해 1회 검색만 사용한다.

## 최종 응답 단계

- 실제 반환된 entry_id/usage_id만 선택한다. 정확한 유래·작품명이 필요하면 반환된 항목의 원문을 읽는다.
- context와 avoid_when을 사용자 상황에 대조한다. 사용자의 부정 조건, 나/상대/제삼자, 관계, 표현 방향을 보존한다.
- safety=avoid는 의미 설명용으로만 사용하고 추천하지 않는다.
- safety=caution은 경고가 없어진 것으로 취급하지 않는다. 필요한 조건이 사용자 말에 명시되어 있고, 위험을 살핀 뒤 미해결 조건이 없을 때만 맥락 한정 추천할 수 있다. 맥락이 없으면 질문하거나 일반 문장으로 바꾼다.
- standard도 모든 상황에서 안전하다는 뜻이 아니므로 피해야 할 조건에 해당하면 추천하지 않는다.
- 추천마다 context_check를 기록한다: assessment, evidence_spans(사용자 원문의 정확한 부분), checked_risk_flags, unresolved_conditions. 이 기록은 AI의 판단이며 사실 인증·사람 검토가 아니다.
- 정확한 감정이나 숨은 말을 알아냈다고 단정하지 않는다. 모호한 ㄹㅇㅋㅋ/아이엠그루트는 가능한 의미를 구분한다.
- “찾지 못했다”와 “찾았지만 이 상황에서는 안 쓰는 편이 낫다”를 구분한다.
- 사용자에게 후보목록 전체를 던지기보다 적합한 하나와 필요할 때 짧은 주의점을 제시한다. 검토용 출력에는 실제 필터·결과·선택과 이유를 별도로 보존한다.

## 기록 형식

계획: id, prompt, action, filters, reason, user_constraints, response_if_no_search.

응답: id, action, selected_entry_id, selected_usage_id, response, reason, context_check.

context_check는 {assessment: compatible|uncertain|incompatible|not_applicable, evidence_spans: [...], checked_risk_flags: [...], unresolved_conditions: [...]}다. 추천의 evidence_spans는 가상 입력에서 실제로 나온 문자열이어야 한다. 해당하는 위험 라벨을 전부 확인했다고 적는 것만으로 적절성이 입증되지는 않는다. 별도 블라인드 평가자가 답 자체를 판정한다.
