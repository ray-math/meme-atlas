# 자연어 평가 결과와 적용 범위

## 무엇을 실제로 실행했나

- Python 검색기 자체는 자연어를 해석하지 않는다. 실제 AI 하위 작업자가 자연어를 구조화 필터로 변환했고, GitHub Actions에서 그 계획으로 Python 검색기를 실행했다. 실제 반환 후보만 다시 AI에 전달해 최종 답변을 만들었다.
- 계획, 실제 검색 trace, 최종 답변, 사전 gold, 사후 판정을 별도 파일과 커밋으로 보존했다. CI 재실행은 저장된 계획의 검색 재현이며 실시간 LLM 호출이 아니다.
- 정확한 모델 버전과 샘플링 설정은 실행 도구에서 제공되지 않았다. AI가 문항을 작성하고 AI가 판정했으며, 사람 검증이나 서로 다른 모델 계열의 독립 검증이 아니다.
- 평가 당시 343개 원문 중 28개 항목의 38개 용례만 주석되어 있다. 나머지 315개를 맥락 추천에서 검색하지 못했다고 밈 자체가 존재하지 않는 것은 아니다.

## 검색과 최종 답변을 혼동하지 않는다

E01–E09에서 엄격한 사전 적합 기준의 원시 검색 상위 1위는 5/9, 반환 후보 전체는 11/24, 적합 후보를 하나 이상 포함한 질의는 9/9였다. 후단 AI가 부적합 후보를 걸러냈으므로 최종 답변의 높은 점수를 검색기 정밀도 100%라고 부르면 안 된다. 일부 후보는 약한 적합으로 제외했으며, lookup에서 반환되었다는 사실 자체가 안전 위반은 아니다.

H12의 정답 후보 회수는 답변 가능한 7/7이었다. recommend 기본 안전 제외 정책과 lookup 후 문맥 검토를 통한 추천은 서로 다른 경로다. 이 평가는 후자를 포함하며, recommend 차단만을 평가한 것이 아니다.

## 발견한 실패와 v3 개발 수정

- A03: 자신의 긴 설명을 뜻했는데 유사한 상황 라벨을 상대 설명 제지로 매핑했다. 올바른 TMI 자기 용법이 이미 존재했으므로 주석 부족이 아니라 계획/필터의 false negative였다. v3는 겹치는 상황 축을 OR로 조회하고, 명시된 자기 방향을 AND로 유지한다. 실제 Python 개발 재실행에서 `tmi/self-overdetail`만 반환되었다.
- E21: 공개 망신 밈은 권하지 않았지만 일반 대안에 '이미 답변했다'는 입력에 없는 사실을 더했다. v3는 추천하지 않는 답변도 사실 근거를 기록하고, 불필요한 과거 사실을 만들지 않게 했다.
- 원 평가자가 변하지 않은 기준으로 두 개발 수정 답변을 다시 판정했고 2/2 적합, 위험 0으로 확인했다. 이는 드러난 실패를 겨냥한 수정 확인이다.
- v2 답변과 점수는 덮어쓰지 않았다. 수정 결과는 `eval/development/v3-fix-*`에 별도로 보존하며 새 미노출 정확도로 세지 않는다.

`docs/ai-usage-contract-v3.md`는 호출자용 지시문이다. Python CLI에 LLM이나 자동 의미 판단 기능이 추가되었다는 뜻이 아니다. context_check/factual_check의 자동 검사는 근거 문자열과 기록 구조만 검사한다. 기록 내용이 참이거나 실제로 안전한지는 별도 판정이 필요하다.

## 단계적 적용 조건

1. 새로운 배치는 후보 수집과 draft 주석까지만 진행하고, 출처·본문 연결·용법 방향·주의 맥락을 검토한 뒤에만 추천용 reviewed 상태로 올린다.
2. 원시 검색 1위나 모든 결과를 그대로 추천하지 않는다. 해당 용법의 context/avoid_when을 검사하며, 미주석·모호함·조회 실패·정책 제외를 구분한다.
3. 공개 검증셋은 이제 개발 회귀다. 추가 수정 후 정확도를 다시 주장하려면 새로운 미노출 질문과 봉인된 기준이 필요하다.
4. 심각한 위험 추천, 입력에 없는 사실 추가, 용법 방향 뒤집힘을 발견하면 자동 승격을 중단하고 원인을 검토한다. 작은 집합의 통과만으로 343개 일괄 자동 태깅을 하지 않는다.
5. 이 변경은 작업 브랜치에 모아 검토한다. main 반영과 수집 재개는 사용자의 최신 지시에 따라 별도로 결정한다.

## 2026-11-17: 기존 공개 56문항 전체 v3 회귀

새 AI 작업자에게 계약·어휘·원래 질문만 주고 계획을 생성했다. 실제 Python 검색 결과를 GitHub Actions에서 얻은 뒤 최종 답변을 생성했고, 원 문항 작성자가 변하지 않은 gold로 다시 판정했다. 질문은 이미 공개되어 있고 v3는 알려진 실패를 반영했으므로 **신규 미노출 정확도 평가가 아니다**.

- A28: 최종 적합 27/28 → 28/28. 추천 17건, 보류 7건, 질문 4건. 위험 판정 0.
- E27 주지표: 26/27 → 27/27. E10 사전 경계 제외 유지. 위험 판정 0.
- A 추천 질의 17건: 올바른 **용법** 회수 16/17 → 17/17, strict top1 11/17 → 13/17, 후보 정밀도 17/32 → 18/28.
- E 추천 질의 9건: 용법 회수 9/9 유지, strict top1 5/9 → 7/9, 후보 정밀도 11/24 → 11/19.

용법 회수는 `scripts/measure_usage_retrieval.py`로 별도 집계했다. 과거 `candidate_recall_hits`는 항목 단위다. 같은 TMI 항목의 반대 방향 용법을 가져온 A03을 항목 회수 성공으로 셀 수 있으므로, 이를 올바른 용법 회수로 해석하면 안 된다. 원시 후보에는 여전히 부적합한 용법이 섞여 있으며 후단 문맥 선별이 필요하다.

### 평가 하네스 무결성 수정

빈 답변 목록·누락/중복 ID, 추천 선택값 누락이 유효한 판정 기록처럼 통과할 수 있는 구조 검사를 수정했다. ID 집합 일치, 명시적 schema 버전, action 종류, plan/trace의 질문·필터·action 일치, 추천 entry/usage 필수 여부를 확인한다. CI는 기대 prompt 버전을 외부 인자로 고정해 v3 기록을 v2로 낮추어 사실 근거 검사를 피하지 못하게 한다.

기존 공개 스냅샷을 수정된 검사기로 다시 실행했으며 기존 최종 적합 점수는 변하지 않았다. 이는 발견한 검사 허점이 기존 보고 점수에 실제로 적용됐다는 뜻은 아니며, 이후 불완전한 기록이 성공으로 오인되는 경로를 막은 것이다. 자동 검사는 구조와 근거 문자열의 존재만 확인하며 의미의 참·거짓이나 안전성을 인증하지 않는다.

## 검증된 본문 보완과 주석 범위

이 작업 브랜치에 UBD·프로불편러·GOAT·폰은정·3대500 본문 5개를 보완해 총 348개가 되었다. 이는 최신 유행 관측이나 새 문맥 주석의 자동 승인과는 다르다. usage 주석은 기존 28개/38용법 그대로이며 미주석 항목은 320개다. 후보대장의 main 포함 상태도 자동 승격하지 않았다. 새 본문은 기존 검색·목차와 coverage에 반영했으며, 과거 평가 trace의 343개 스냅샷은 변경하지 않았다.
