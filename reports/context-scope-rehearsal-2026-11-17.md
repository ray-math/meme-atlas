# 명시 문맥 검색: 공개 개발 리허설

## 원인과 변경

특수 용례도 미지정 축을 무제한으로 받아들여 일반 칭찬·사실확인·기대현실 질의에 섞였다. 가나다순 동률 정렬은 이 혼입을 상위 결과로 만들 수 있었다. 정렬 점수만 조정하지 않고 용례별 최소 명시 상황/대상 조건을 추가했다.

GOAT는 스포츠선수평가/제삼자, 폰~은 허구확인후/상황, 오히려 좋아는 구체적이점발견/상황을 요구한다. 넓은 OR는 충족으로 간주하지 않는다. 정확한 표제 lookup은 뜻설명만 허용하며 추천에는 우회가 없다. 이 조건은 호출자가 제공한 필터이지 엔진의 사실·관계·안전 검증이 아니다. 기본 diagnostics는 기존 응답 호환을 위해 opt-in이다. 누락 조건을 채워도 risk/safety/draft 등 다른 gate로 제외될 수 있다.

## 실제 실행과 한계

- 공개 profile 예문 3개, GOAT의 공개 context+예문 1개, 기존 공개 A 입력6개로 총10개를 구성했다. 차단된 비공개 검증 세트는 사용하지 않았다.
- 별도 AI가 원 gold·과거 계획·결과를 읽지 않고 실제로 계획을 만들었다. 다만 공개 주석 기반이며 긍정 예문에 밈 이름이 이미 있다. 새로운 표현 발견·독립 홀드아웃·일반 정확도 시험이 아니다.
- GitHub Actions 43998103842에서 실제 Python search를 호출했다. 새 세 profile은 메모리 복사에서만 reviewed로 바꾸고 원본 draft를 변경하지 않았다.
- 그 결과를 읽은 AI가 실제 최종 선택/답안을 작성했다. CI 재실행은 저장 계획의 Python replay이며 새 LLM 호출이 아니다.
- 동결 자료: [계획](../eval/context-scope/plans.json), [검색](../eval/context-scope/retrieval.json), [답안](../eval/context-scope/answers.json).

## 관찰 결과

폰~과 오히려 좋아의 공개 예문은 좁은 상황/대상 조건으로 각 용법 하나를 찾았다. GOAT는 원 예문에 스포츠·대상 정보가 부족했고, context를 붙여도 수신자와 평가 대상 관계가 명확하지 않아 두 번 모두 질문으로 남겼다. 좋은 결과를 강제로 만들려고 빠진 조건을 주석 태그에서 복원하지 않았다.

기존 A01 문학상 후보 감탄, A12 실제로 확인된 황당한 소식, A16 자기 계획의 초라한 결과에는 각각 GOAT·폰~·오히려 좋아가 혼입되지 않았다. A17 가족상, A19 확인 안 된 소문 확정 요청, A20 휴식 의사를 무시하는 압박은 검색·밈 선택을 보류했다.

이 관찰은 10건의 주석 파생 개발 결과다. 사용 맥락을 AI가 잘못 필터링하면 gate도 잘못 충족할 수 있다. 더 보수적인 요건 때문에 명확하지 않은 긍정 요청을 놓치는 비용도 있다. GOAT의 질문 결과를 추천 성공으로 세지 않는다.

## 다음 판단

폰~·오히려 좋아는 출처·용례별 재검토와 이 개발 재현 결과를 바탕으로 제한적 reviewed 승격 여부를 판단한다. 폰~은 caution이라 기본 추천에서는 계속 제외된다. GOAT와 가보자고는 보류 상태이며 추가 근거·맥락 평가를 별도로 진행한다. 기존28 주석·원래 답안과 gold·과거 검색 회귀는 변경하지 않는다.

## 독립 AI 재검토 및 제한 승격

동결10건의 선택·사실 추가 여부를 다른 AI가 재검토해 부적합한 적용이나 새 사실 추가를 발견하지 못했다. P-pon은 lookup의 caution 후보를 최종 AI가 문맥 검토해 선택한 것이며 엔진 recommend 통과가 아니다. A01/A12/A16의 새 계획은 각각 감탄/예상밖사실/자기 필터 자체로도 특수용법을 제외하므로, 이 세 결과만으로 gate의 인과 효과를 주장하지 않는다. gate 효과의 근거는 바꾸지 않은 과거 broad-plan을 사용한 별도 실제 Python 비교다.

폰~·오히려 좋아 2profiles/2uses만 제한적으로 승격했다. 현재 reviewed33profiles/45uses, draft2profiles/3uses(GOAT·가보자고), 미주석313개다. 폰~은 caution이며 기본추천에서 제외, 오히려좋아도 명시필터를 모두 만족해야 후보가 된다. GOAT는 실제 긍정 문맥이 충분한 별도 검증 전 보류한다.

동결 검색 스냅샷의 coverage는 원본31 reviewed 상태의 baseline이다. 임시 메모리에서 세 profile을 reviewed로 바꾼 수와 혼동하지 않는다. 현재 replay는 baseline과 provisional 수를 따로 명시한다. 과거 스냅샷 수치를 새 승격 수로 덮어쓰지 않는다.
