## 편집 위험 경계

공개 실패 조롱, 피해 호소를 트집으로 묵살하기, 확인되지 않은 거짓말 지목, 실제 복장 통제·중량 수행 압박, 상실·질병의 억지 긍정, 휴식 의사 무시·위험 행동 독려는 적합한 추천 상황으로 만들지 않는다. 이 경계는 기사에서 통계적으로 검증된 안전 등급이 아니라 편집 판단이다. standard 역시 좁은 context와 avoid_when을 확인해야 한다.

수량비유·호칭재전유·긍정적재해석 의도와 도전시작 상황을 좁게 정의한다. 기존 상태설명·자기강조·불확실한결과에 억지로 맞추지 않는다. 새로운 별칭 확장이나 의미가 다른 태그의 자동 동의어 처리는 하지 않는다.

## 승격 전 남은 검증

draft는 검색·추천에 노출하지 않는다. 본문과 용법 정합성, 대상 방향, 실제/편집 예문의 구분, 부적합 맥락의 누락을 독립 검토하고 새 자연어 질의로 실패 유형을 확인한 뒤 개별 승격 여부를 결정한다. 기존 공개 평가의 재통과를 새 용법의 정확도로 주장하지 않는다. main 반영은 별도 승인 전 보류한다.

## 다음 반복용 실패 차단 명령

개별 후보를 메모리 안에서만 reviewed로 복사해 실제 Python 검색을 검사할 수 있다. 파일·검토 상태는 변경하지 않는다.

```sh
python scripts/evaluate_draft_readiness.py --candidate goat --fail-on-drift
python scripts/evaluate_draft_readiness.py --candidate ubd --candidate pro-offended --candidate three-lifts-500 --fail-on-drift
```

첫 명령은 현재 공개 질의의 후보 혼입 때문에 실패해야 한다. 두 번째는 이번 제한 승격 집합의 구조 및 공개 v2/v3 후보 보존 검사다. 검사는 기존 공개 데이터만 사용하며, 독립 자연어 평가를 대신하지 않는다. unknown/빈 후보 ID는 오류 처리하고, 전체10용법 기본 실행은 진단 결과를 출력하되 drift 자체를 자동 승인 근거로 삼지 않는다.

### 검사기 자체의 후속 감사

CLI의 drift 키 불일치를 실제 실행에서 발견해 수정했고, 종료코드0/1/2를 subprocess로 검사한다. 선택 profile의 일부가 누락되거나 usages가 비어 있으면 부분 성공으로 처리하지 않는다. unknown 상태와 빈 정서목록 자체를 확인하며, 공개 계획의 오류를 빈 후보끼리 일치했다고 통과시키지 않는다.

이미 reviewed인 집합을 다시 임시승격하는 현재 비교는 no-op 성격이다. 해당 집합의 실제 승인 근거는 승격 당시 검사와 변경하지 않은 과거 frozen 회귀의 재실행이며, 이 명령만을 독립 승격 검증으로 해석하지 않는다. drift는 기존 공개계획의 limit 안 후보ID/순서 변화만 측정한다. 전체 공간·새 자연어·실제 생성 안전성을 보장하지 않는다.
