# 가보자고 자기격려와 GOAT 대상 조건 재검토

## 가보자고의 추가 직접 자료

- [CJ문화재단, 2023-03-14](https://www.cjazit.org/support/tune-up/entry/64/26182?p=72): 창작자가 밈을 차용한 곡을 소개하며 자기 자신을 북돋는 문맥을 보여 준다. 노래 속 표현의 존재이지 일반인의 내면·행동을 증명하지 않는다. 가사는 복사·저장하지 않았다.
- [작담이 통신, 2025-09-12](https://maily.so/jakdamreport/posts/8mo54w71z9p): 작성자가 작업 현장으로 가는 차에서 혼자 표현을 사용했다고 서술한다. 작업 시작 전 자기격려의 직접 자기보고이며 녹음 검증·일반적 효과 증거는 아니다. 글의 걱정에 관한 일반화는 사전 사실로 옮기지 않았다.

기존 상대 격려와 자기격려를 분리한다. 과거 draft의 commit-to-start/다짐은 근거보다 실행 약속을 강하게 읽을 수 있어 encourage-self/격려+자기로 좁혔다. 자기격려라는 새 intent를 만들지 않고 기능과 대상 축을 사용한다. 감정은 unknown/[]다. 일상 자기응원 전부를 분류하지 않고, 선택한 과제에 착수하는 맥락만 도전시작으로 다룬다. 상대 격려는 상대의 도전 의사, 자기격려는 자기 선택을 전제하며 휴식 무시·위험 행동 권유는 제외한다.

## GOAT의 질문 비용

최고의 선수라는 평가를 직접 선수에게 말하든 다른 사람에게 설명하든 찬사의 핵심 의미는 같다. target을 제삼자에 고정한 것은 불필요한 관계 질문을 만들 수 있었다. 대상 범위를 상대/제삼자로 표시하고, 스포츠선수평가만 필수 검색 조건으로 유지한다. 대상이 명시되면 필터링하되 불명확하면 생략한다. 이는 의미에 근거한 편집 판단이며 직접 선수에게 보낸 실제 발화의 독립 실례를 추가 확보했다는 뜻이 아니다. 자기 GOAT·비인간·반어 파생은 포함하지 않는다.

과거 GOAT 두 질문 응답은 그대로 보존한다. 새 조건의 실행은 새 개발 반복이며, 옛 응답을 덮어써 성공률을 높이지 않는다. 일반 칭찬은 스포츠 조건이 없어 계속 제외되어야 한다.

## 검증 범위

모두 기존 공개 본문·예문과 공개 가상 반례에 대한 개발 검증이다. 출처 확인, 구조적 검색, 실제 AI의 문맥 판단을 구별한다. 사람의 독립 평가나 미노출 일반화 정확도를 주장하지 않는다. main 병합은 별도 승인 전 보류한다.

## 실제 실행 및 최종 검토

새 공개8건은 이전10건과 별도 파일로 보존했다. 실제 AI가 계획을 만들고 GitHub Actions43999696034에서 Python search를 실행한 뒤 AI가 결과를 선택했다. [계획](../eval/direction-scope/plans.json), [검색](../eval/direction-scope/retrieval.json), [최종답안](../eval/direction-scope/answers.json)을 동결했다. 이후 다른 AI가 8건의 선택·사실 추가·부적합 맥락을 검토했다.

스포츠 여부가 없는 GOAT 원 예문은 질문을 유지했고, 스포츠 평가 context가 있는 동일 표현은 불필요한 수신자 질문 없이 선택했다. 가보자고의 명시된 자기/상대 시작 맥락은 서로 다른 용법으로 선택했다. 문학상 후보 감탄은 기존 대박, 자기 게임 연습의 거친 지속 의지는 기존 존버를 선택했다. 휴식 의사 무시와 친절에서 연애 의사를 확정하는 요청은 검색 전에 보류했다.

A01 비혼입은 감탄/칭찬 기능 차이, A28 비혼입은 다짐/격려 기능 차이만으로도 설명된다. requirements 자체의 효과는 별도 고정 broad-plan·필수조건 대칭 검사에 근거한다. 검색 전 보류는 AI의 판단이지 Python의 부정 문맥 이해 증거가 아니다. 8건 모두 공개 편집조건 기반이며 독립 발견 정확도 검증이 아니다.

GOAT·가보자고의 현재 좁힌 용례만 reviewed로 전환했다. 현재 본문348개 중 주석35개/48용법이 reviewed이고313개는 여전히 미주석이다. 원28개/38용법은 변경하지 않았다. 새7개/10용법은 일괄 승격이 아니라 보류·오류 발견·조건 수정·개별 재검토를 거쳤다. standard15/caution31/avoid2이며 safety는 문맥별 편집 판단이지 안전 인증이 아니다.

main은 승인 전 병합하지 않았다. 미래의 새 후보에도 현재 결과를 일반화하여 자동 승격하지 않는다.
